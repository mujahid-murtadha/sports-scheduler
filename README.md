# نسق: نظام جدولة المرافق الرياضية

محرّك جدولة ذكي (مسألة إشباع قيود CSP + بحث بالتراجع، مبني من الصفر بلا مكتبات حل) مع خادم Express وقاعدة بيانات PostgreSQL وواجهة ويب عربية.

## ما يقدّمه النظام

- **الجدولة الآلية**: توزيع طلبات الفرق على المرافق دون أي تعارض، مع مراعاة الأوقات المفضّلة والعدالة بين الفرق وتوزيع الحمل بين المرافق المتماثلة، وتفسير مكتوب لكل قرار.
- **إعادة الجدولة بأقل تغيير**: عند إضافة طلب أو إغلاق فترة أو إيقاف مرفق، يُنقل المتأثر فقط وتبقى بقية الحجوزات في مواعيدها.
- **فترات الإغلاق**: صيانة أو مباراة رسمية أو فعالية في ساعات محددة من يوم معيّن.
- **التثبيت والجدولة اليدوية**: تثبيت حجز في موعده، أو نقله، أو حجز طلب غير ملبّى في موعد يختاره المدير؛ والنظام يعرض المواعيد الصالحة فقط ويفحص كل موضع بالقيود الصلبة نفسها.
- **الجدول**: عرض يومي لكل المرافق، وأسبوعي لكل مرفق، وجدول لكل فريق قابل للطباعة، وتصدير CSV.
- **لوحة المتابعة والتقارير**: الإشغال حسب اليوم والساعة، عدالة التوزيع (مؤشر Jain)، الطلب مقارنة بالطاقة، ومقارنة المحرّك بالتوزيع اليدوي بالأسبقية.
- **لوحة العرض العامة**: شاشة لمدخل المركز تعرض جلسات اليوم والجلسة الجارية (تُفعَّل من الإعدادات).
- **المستخدمون وسجل النشاط**: حسابات متعددة بكلمات مرور مشفّرة، وسجل تدقيق لكل عملية: من فعلها ومتى.
- **العربية والإنجليزية**: تنعكس الواجهة كاملة (من اليمين لليسار أو العكس)، وتصل رسائل الخادم وتفسيرات المحرّك وسجل النشاط باللغة المختارة.
- **الوضعان الفاتح والداكن**: يتبع إعداد الجهاز تلقائياً، ويمكن تبديله من أعلى الصفحة.

## التشغيل

المتطلبات: Node.js 20 أو أحدث، و PostgreSQL 14 أو أحدث.

1. أنشئ قاعدة البيانات (مرة واحدة):

       createdb -U postgres sports_scheduler

2. ثبّت المكتبات (مرة واحدة):

       npm install

3. شغّل الخادم (غيّر كلمة المرور في الرابط إلى كلمة مرور PostgreSQL عندك):

       # Windows (PowerShell)
       $env:DATABASE_URL="postgres://postgres:كلمة_المرور@localhost:5432/sports_scheduler"; npm start
       # Linux / macOS
       DATABASE_URL="postgres://postgres:كلمة_المرور@localhost:5432/sports_scheduler" npm start

4. افتح http://localhost:3000 وسجّل الدخول:

       اسم المستخدم: admin
       كلمة المرور:  admin123

   غيّر كلمة المرور من صفحة «الإعدادات» بعد أول دخول.

5. للتجربة: «الإعدادات» ثم «تحميل بيانات تجريبية»، ثم اضغط «تشغيل الجدولة».

الجداول وحساب المدير تُنشأ تلقائياً عند أول تشغيل.

## أوامر أخرى (لا تحتاج قاعدة بيانات)

    npm test            # الاختبارات الآلية (14 اختباراً)
    npm run benchmark   # السيناريو المرجعي + المقارنة، النتائج في results/benchmark.json
    npm run stress      # سيناريو الضغط الذي يُظهر التراجع
    npm run typecheck   # فحص الأنواع في TypeScript

    src/engine/scheduler.ts    المحرّك: CSP + التراجع + الفحص الأمامي + MRV + التفسير
    src/engine/metrics.ts      المدقّق المستقل، فحص الموضع اليدوي، المؤشرات
    src/baseline/fcfs.ts       محاكاة الجدولة اليدوية (الأسبقية في الطلب)
    src/scenario/reference.ts  السيناريو المرجعي (4 مرافق، 20 فريقاً، 121 طلباً)
    src/scenario/stress.ts     سيناريو الضغط (امتلاء 100%)
    src/server/index.ts        الخادم ومساراته (REST)
    src/server/scheduling.ts   الربط بين قاعدة البيانات والمحرّك، والجدولة اليدوية
    src/server/auth.ts         تسجيل الدخول وتشفير كلمات المرور والجلسات
    src/server/http.ts         التحقق من المدخلات

    src/server/db.ts           الاتصال بقاعدة البيانات

    public/i18n.js             اللغة والاتجاه، وصياغة تفسيرات المحرّك وسجل النشاط باللغتين
    public/styles.css          نظام التصميم

    public/icons.svg           الأيقونات ومخططات الملاعب المصغّرة
